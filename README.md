# Zhou Yu's Blog

A static personal blog built from scratch with Astro 7 and the official Markdoc integration. No blog template, React, or Tailwind.

The layout follows a compact, text-first approach: inline project links, a shared post list, and locally hosted Source Serif 4 fonts. The weight-only font files keep the normal and italic faces to about 102 KB combined; only the normal face is preloaded. Home shows the five most recent posts, while the archive lists every published post by year.

## Local development

Use Node.js 24 (minimum 22.12) and pnpm 11.

```sh
pnpm install
pnpm dev
pnpm build
pnpm preview
```

`pnpm build` runs Astro's type checker before generating `dist/`. Use `pnpm format:check` to check formatting.

## Writing posts

Create a `.mdoc` file in `src/content/posts/`. Its filename determines the post URL: for example, `hello.mdoc` becomes `/posts/hello/`.

```md
---
title: Post title
description: A one-line summary.
publishedAt: 2026-09-29
lang: en # Use zh-CN for Chinese posts.
# Optional, after a meaningful revision:
# updatedAt: 2026-10-01
draft: false
---

## Start here

Write the body in Markdoc, with links, images, lists, blockquotes, and syntax-highlighted code.
```

Posts with `draft: true` are excluded from the home page, archive, generated pages, RSS, and sitemap. Posts appear in reverse chronological order. Markdoc extensions live in `markdoc.config.mjs`.

Section headings link to their own anchors. Posts with at least three level-two headings get a collapsible table of contents, using the same IDs generated by Markdoc. `updatedAt` adds a visible revision date and updates the article metadata.

### Images

Keep article photos and screenshots in `src/assets/` and link to them relative to the post. Astro infers their dimensions and generates responsive WebP files up to 1320px wide. SVG and GIF keep their formats.

```md
![Describe the screenshot](../../assets/example.png)
```

For images in `public/` or on another website, supply their original dimensions with the image tag. These URLs are served as-is; dimensions reserve space before loading. A missing size fails the build with an explanation instead of shipping an image that shifts the page.

```md
{% image src="/photos/example.jpg" alt="Describe the photo" width=1200 height=800 /%}
```

Images load lazily by default. Use `loading="eager"` on the image tag for an image that is part of the first screen. The original `/assets/swallow.svg` still uses its dedicated animated component.

### Subscription and sharing

`/rss.xml` uses the same published-post list as the site. Every page declares the feed for RSS readers, and the footer has a subscription link.

The shared preview image is `public/og.png` (1200 × 630); its editable SVG source is `src/assets/social-card.svg`. Run `pnpm og:generate` after editing the SVG. Page titles and descriptions appear in Open Graph and Twitter card metadata. Published articles also include `BlogPosting` JSON-LD with their canonical URL, author, publication date, and optional revision date.

## Structure

- `src/pages/`: Home, post archive, post pages, RSS, and 404.
- `src/layouts/SiteLayout.astro`: Shared page layout and metadata.
- `src/content.config.ts`: Markdoc content collection and validation.
- `src/data/site.ts`: Profile information and project links.
- `src/styles/global.css`: Site styles and responsive layouts.
- `public/favicon.svg`, `public/favicon.png`, `public/assets/swallow.svg`: Original swallow assets.

The original post, “My Third Blog,” has been translated into English and keeps its `/posts/my-third-blog/` URL and publication date. Its references to earlier blog templates reflect the original 2023 post. The swallow SVG files remain unchanged; display components fit the artwork to the layout and provide a static alternative for reduced-motion preferences.

The notes on this rebuild are published as “My Fourth Blog” at `/posts/my-fourth-blog/`. Each post can set `lang` to `en` (the default) or `zh-CN`; the article page uses it for HTML language, Open Graph locale, and structured metadata.

## Deployment

The site URL is `https://yuzhouu.github.io/`. Select **GitHub Actions** in the GitHub Pages settings. Pushing to `main` runs the workflow to check, build, and deploy the site. No server or additional adapter is needed.
